# Text and localization

Every player-facing field (`title`, `summary`, `journal`, dialogue `text`, choice `text`, outcome `title`) is typed `text`. A `text` value is one of:

- a literal string: `Find the harbormaster's ledger`
- a key: `@harbormasters_ledger.find.title`

Literals are the default and the fast path. Keys are for teams that localize.

## Extraction

`@oqf/i18n` provides two operations.

`extract` walks a pack, moves every literal into a table, and rewrites the source to keys. Keys are generated from structure so they are stable across runs: `<questId>.<stepId>.<field>`, `<conversationId>.<nodeId>.text`, `<conversationId>.<nodeId>.<choiceIndex>.text`. A literal that already has a key is left alone. The table is written as a flat JSON map by default, or as CSV, PO, or XLIFF through small adapters.

`inject` does the reverse: reads a table and writes literals back, for anyone who wants to leave the localized workflow.

Both are pure transformations over the model, so they work on compact and JSON alike.

## Arguments

A text value may carry placeholders of the form `{name}`. When the runtime hands a text out, it hands the arguments along with it ([D29](00-decisions.md)):

| Argument | Value |
|----------|-------|
| `{<param>}` | The bound value of each quest parameter, by name. |
| `{count}` | The step's objective counter. Only for a step's `title` and `journal`. |
| `{target}` | The step's objective threshold, after parameters are substituted. Only for a step's `title` and `journal`. |

A quest's `title` and `summary` and an outcome's `title` receive the parameters only. OQF passes the map; the game formats. A game that wants "1 fish, 2 fish" plural rules uses its own formatter, since those rules differ per language and per library. The resolver `@oqf/i18n` ships does plain substitution: each `{name}` is replaced by the argument's string form, unknown names are left as they are.

Placeholders are part of the string. `extract` and `inject` carry them through untouched, so a translator sees `Catch {n} {fish}` and may reorder the placeholders.

## Runtime

The runtime does not translate. It hands out whatever the field holds, plus the arguments above. A game that uses keys resolves them through its own localization layer, or through a tiny resolver `@oqf/i18n` ships that takes a table and a locale.

## Mixed files

A file may mix literals and keys. The validator warns in strict mode when a pack has both, since that usually means an extraction was missed.
